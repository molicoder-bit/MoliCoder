**Started:** 2026-10-15. Update facts from primary provider documentation immediately before any integration or purchase decision.

## Rules for entries

1. Create one row per **provider-specific offering**, not one row per shared model name. A model served by two providers has two price, quota, privacy, latency, and eligibility records.
2. Classify each offering as `recurring free API`, `temporary trial/promotion`, `paid metered API`, `subscription programmable inference`, `interactive-only CLI/app`, `automation-compatible coding agent`, or `local inference`. “Free CLI” never implies free inference.
3. Enter `unknown` when a fact is not documented. An unknown metered price, automation permission, or privacy term blocks eligibility for autonomous use until resolved.
4. Put official source URLs and the checked date beside the exact claim. A pricing page does not prove permission for unattended agents; a CLI help page does not prove subscription entitlement.
5. Normalize metered prices to USD per million input/output tokens, but retain the provider's billing units, cache/write/reasoning treatment, and regional exceptions. Subscription allowances are recorded in their own units and must not be converted into fictitious dollars or tokens.
6. Mark whether a field was verified by official documentation, a local no-cost probe, measured benchmark, or remains an assumption. Record the observer and confidence.
7. Do not put API keys, OAuth tokens, account identifiers, or secret-bearing outputs in this file.

### Comparable direct-endpoint latency test for I16-03

Use the same model/version through a direct endpoint and a gateway where both paths exist. Pin region, client machine, network, SDK/API version, prompt, context size, output cap, temperature, streaming mode, and tools. Run separate cold and warmed series with at least 30 successful samples per path, interleave path order, and retain 429/timeouts as failures rather than dropping them. Measure request start to first streamed token, request start to completion, input/output tokens, retries, error codes, and billed amount; report median, p95, sample count and confidence interval. Repeat for short chat, repository-context planning, tool-call, and long-output coding tasks. A provider's advertised tokens/second is not a measured end-to-end result. No live, chargeable, or credentialed call was made in P02-02.

### Gateway integration decisions for later design

1. Model selection needs a **provider-specific route key**, catalog timestamp, source URL, data-policy class, and price schedule, even if a gateway presents one model name. Rotating `auto` routes are policy-ineligible until the selected provider is visible and approved per request.
2. Gateway account balance and its own caps do not replace MoliCoder's atomic local reservation and hard stop. Check auto top-up, separate processing fees, BYOK billing, retries, and failover before any paid dispatch.
3. Compare direct and gateway paths with the same model/provider pair using the P02-02 latency protocol. Treat gateway overhead, route changes, retries, and data-processing differences as measured facts, never assumptions.
4. OpenRouter isolation from EcoDominicano is a prerequisite for any MoliCoder OpenRouter experiment. It is an architecture constraint, not an instruction to create or fund an account now.

### Hardware and local model gate

Read-only Windows inspection on 2026-10-15 found **32 GB system RAM**, **NVIDIA GeForce RTX 5060 with 8,151 MiB VRAM**, and Ollama 0.35.1. The installed 7B Q4 and 8B Q4 models are immediate, no-download smoke-test candidates; 8B Q6 at 6.7 GB weights may leave little VRAM for KV cache and context. Ollama's official catalog lists `qwen3:4b` at 2.5 GB and `qwen3:8b` at 5.2 GB as possible future alternatives, but installation/download is a later setup decision. File size is only a lower bound: runtime buffers and a larger context consume additional RAM/VRAM. Benchmarks must measure load time, first token, throughput, context capacity, tool-call reliability, and accepted coding tasks on this device before any local routing preference. [Ollama Qwen3 catalog](https://ollama.com/library/qwen3), [llama.cpp build and memory behavior](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md).
