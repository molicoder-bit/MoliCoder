S007/S010 follow-up: the sequential runner previously rejected every task without a Git file change. That made a genuinely empty directory impossible and treated an already satisfied request as failure. Plans now carry optional, reviewable `directory_empty` and `file_equals` checks. The runner verifies them independently during task and final validation, records a no-change completion only with an explicit passing check, and confirms empty-directory creation during Apply. The UI S007 regression exercises the actual Apply action; S010 asserts an unchanged commit and exact file content. A negative test proves a mismatched file cannot pass as a no-op.

Plan review correction: artifact checks were initially summarized by kind and path in the approval dialog, hiding the exact `file_equals` value. The review now displays the complete check JSON before authorization.

S033 follow-up: declining the plan dialog used to leave no durable rejection decision. The UI now records `denied` against the exact plan scope and a `plan_rejected` event, while retaining the plan for inspection. The regression confirms execution remains blocked and no executor or project change occurs.

S034–S036 follow-up: the plan review previously allowed approval or rejection only. Internal Build review now opens a JSON task-plan editor. Its save path checks the exact prior revision and Git base, validates task scope and dependency graph, recomputes runner assignments, and saves a new plan row without carrying approval forward. Regressions add a task through the UI and apply its output, reject a removal with a dangling edge, and confirm an edited dependency changes execution order. A stale editor save cannot overwrite a newer revision.

S038 follow-up: pasted runner/model assignment keys were silently ignored by the plan parser when entered in the new editor. The editor now rejects those keys with an explicit unsupported-override message; no revision or execution is created. Per-task overrides remain a capability gap rather than a simulated success.

S041/S043 fixture correction: the first local-route test used the approval fixture's `hello.txt` task validator after changing the task to `greeting.txt`. Local execution succeeded, validation failed against the wrong file, and the provider fallback changed an out-of-scope path. The fixture now validates the intended file. The scenario confirms a low-risk existing-file edit is assigned to and completed by the local executor, with no provider call.

S044/S045 follow-up: injected service outage and missing-auth errors now have scenario assertions for one attempted dispatch, a clear task/run state, and no project mutation. These are fake-provider faults; real provider entitlement and outage recovery remain unmeasured.

S040 catalog correction: the old test checked a project HEAD change before approved execution, which does not exercise replanning after partial completion. The harness no longer labels that test S040; S040 is `NOT_RUN` until preservation/reuse of accepted work after replanning is verified.
